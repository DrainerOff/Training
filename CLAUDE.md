# Training — как здесь работает Claude

Офлайн-PWA для силовых тренировок на iPhone (Preact, IndexedDB, Service Worker), синхронизация с Google Таблицей через Apps Script, публикация на GitHub Pages: https://draineroff.github.io/Training/. Интерфейс и тексты для владельца — по-русски. Подробности: [README.md](README.md), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/RELEASING.md](docs/RELEASING.md), [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

## Порядок выпуска

1. **Ветка и PR.** Каждое изменение — в своей ветке, PR в `main`. В `main` напрямую ничего не пушится.
2. **Тесты.** `npm test` (unit и Apps Script) и `npm run test:e2e` (Playwright, эмуляция iPhone). Баг сначала воспроизводится тестом, который падает на текущем `main`, потом исправляется. Тесты только на синтетике.
3. **Версия.** `VERSION` в `app/js/main.js`, `version` в `package.json` и `package-lock.json`, раздел `## vX.Y.Z — дата` в [CHANGELOG.md](CHANGELOG.md). Раздел пишется для владельца, а не для разработчика: он становится текстом GitHub Release.
4. **Verifier — перед открытием PR, который меняет `app/js`** (логику, хранение, логику экранов). Запустить агента `verifier` ([.claude/agents/verifier.md](.claude/agents/verifier.md)) и дать ему:
   - SHA или ветку изменения;
   - спеку: текст задачи владельца и запись CHANGELOG этой версии;
   - как запускать: `npm test`, `npm run test:e2e` и особенности окружения (ниже).

   Каждую подтверждённую находку исправить до приёмки, с тестом на её сценарий; спорную — показать владельцу. Изменения только стилей (`app/css`), скриншотов и документации идут без verifier.
5. **PR → зелёный CI → приёмка.** В [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md) раздел версии: шаги проверки на iPhone и отдельный пункт **«Что нашёл verifier и что исправлено»** (или «verifier ничего не нашёл»). Владелец проверяет на своём iPhone.
6. **Merge** (squash) — только после явного «да» владельца. Потом дождаться зелёного «Tests and publish» на `main`; последний коммит `gh-pages` — `Publish <сборка> from main`.
7. **Release** — после того как владелец проверил новую сборку на iPhone и сказал «ок»: **Actions → Release → Run workflow** (версия `X.Y.Z`). Тег из облачной сессии не пушится — только через workflow. Выпускать сразу после проверки: если тем временем в `main` попадёт другой PR, workflow откажется выпускать эту версию.

## Данные владельца

- Личные данные о здоровье и тренировках (Apple Health, Zepp Life, Fitdays+, реальные веса и подходы из таблицы) никогда не попадают в коммиты, PR, CI, логи и публичные страницы. В тестах и скриншотах — только синтетика.
- Реальная Google Таблица: без изменения данных, массового импорта, удаления старых записей и разрушительных миграций без явного одобрения владельца. Восемь исходных листов не трогаются, новое — в листах `App_*`. URL и ключи Apps Script прежние.
- `apps-script/Code.gs` владелец ставит сам: резервная копия таблицы → вставить код → **Управление развертываниями → ✎ → Новая версия** (тот же `/exec` URL). Дать точные шаги и ждать его подтверждения. Старая версия приложения должна работать с новым скриптом и наоборот.
- База на телефоне (`DB_VERSION` в `app/js/data/db.js`) меняется только добавлением хранилищ, со сквозным тестом обновления с прошлого выпуска ([docs/RELEASING.md](docs/RELEASING.md)).
- Имена файлов не должны попадать под фильтры блокировщиков контента (`tests/unit/blockers.test.js`).

## Окружение облачной сессии

- Playwright закреплён на 1.56.1, а в контейнере предустановлен другой Chromium: для e2e нужен локальный конфиг с `use.launchOptions.executablePath: '/opt/pw-browsers/chromium'` (его не коммитить). `playwright install` не запускать.
- Во многих e2e часы зафиксированы: два одинаковых подхода подряд считаются двойным нажатием — меняйте повторения между ними.

## Тексты для владельца

- Инструкции — с точными русскими названиями действий iOS и приложений.
- Меню «Тренировки» в таблице видно только в браузере на компьютере.

## Браузер и поиск в интернете

- Если сайт не пускает встроенный браузер или обычные запросы (капча, 403, «проверка на робота», пустая страница) — не искать обходы и не переключаться на источники похуже: сразу открыть этот сайт через расширение Claude in Chrome.
- Поиск по маркетплейсам (Ozon, Wildberries, Яндекс Маркет, Авито, AliExpress и другие) всегда начинать с расширения Claude in Chrome, если оно доступно.
- Если расширения в сессии нет (например, облачная сессия без подключённого компьютера) — сказать об этом владельцу одной строкой в начале и дальше искать обычным поиском, не перебирая обходные пути.
